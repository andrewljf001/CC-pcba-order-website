## 三、技术栈

| 层级 | 技术选型 | 说明 |
|------|---------|------|
| 前端 | HTML + CSS + JS | 极客绿黑风，单文件可独立运行 |
| 后台 CMS | Strapi v5（自托管） | 报价管理/订单管理/内容管理 |
| 数据库 | PostgreSQL | Strapi 官方推荐 |
| 文件存储 | Cloudflare R2 | 客户上传文件，不占 VPS 磁盘 |
| 支付 | PayPal API + PingPong B2B | 小单自动/大单人工 |
| 邮件通知 | Resend / SendGrid | 询价通知/状态变更通知 |
| 本地工具 | Node.js + Playwright | Mac 本地运行，供应商状态同步 |

## 四、数据存储策略

### 放在 PostgreSQL（VPS）
- 订单信息（客户资料/需求/状态/报价）
- 报价参数表（随市场动态调整）
- 供应商信息表
- 订单号映射表（网站订单号 ↔ 供应商订单号）
- 支付记录
- 用户账号（运营人员）

### 放在 Cloudflare R2（对象存储）
- 客户上传：Gerber 文件
- 客户上传：BOM 文件
- 客户上传：Pick & Place 坐标文件
- 生产文件：测试报告、出货照片

### 放在 Mac 本地（同步工具）
- 供应商账号登录状态（浏览器 Cookie）
- 同步日志

## 五、支付架构

### PayPal（小单）
```
客户点击支付 → PayPal 收银台 → 支付成功回调
→ Webhook 通知 Strapi → 自动更新订单状态为"已付款"
```

### PingPong B2B（大单/电汇）
```
运营发送电汇账户信息给客户 → 客户完成电汇
→ 运营在后台手动确认到账 → 手动更新订单状态
```

## 六、本地同步工具架构

### 技术方案
- **语言**：Node.js
- **浏览器自动化**：Playwright（控制本地 Chrome）
- **运行方式**：Mac 菜单栏 APP（后期封装），初期命令行运行
- **触发方式**：定时自动 + 手动触发两种模式

### 供应商适配器接口规范
每个适配器实现以下标准接口：
```javascript
{
  name: '嘉立创',
  login()       // 登录供应商后台
  getOrderStatus(supplierOrderId)  // 抓取订单状态
  mapStatus(rawStatus)  // 转换为标准状态格式
}
```

### 标准订单状态（统一格式）
```
inquiry_received   // 收到询价
quote_sent         // 已发报价
payment_confirmed  // 付款确认
in_production      // 生产中
qc_inspection      // 品质检验
shipped            // 已发货
completed          // 完成
```

### 安全机制
- 所有供应商账号凭证仅存 Mac 本地，不上传 VPS
- 同步 API 使用 Token 鉴权
- 同步日志本地保存，便于排查问题
