# 📦 数据恢复指南（出事了看这一篇）

> **什么时候用这篇文档？**
> 当你发现网站数据出问题了 —— 订单没了、客户账号丢了、数据被误删或改错、数据库坏了。
> 跟着下面的步骤走，从备份里把数据找回来。**不需要懂代码，照抄命令即可。**

---

## ⚠️ 开始之前，先冷静

1. **不要慌，数据大概率还在。** 系统每天凌晨 3 点自动备份，最多丢失当天的少量数据。
2. **不要再去后台乱点乱删**，避免情况更糟。
3. 准备好用电脑 SSH 登录服务器（就是平时更新网站用的那个黑色终端）。

---

## 🔧 第一步：登录服务器

打开终端，SSH 连上 VPS（和平时更新代码一样），然后进入项目目录：

```bash
cd /var/www/pcbaforge
```

---

## 📋 第二步：看看有哪些备份可以用

输入这条命令，列出所有备份：

```bash
node restore.js --list
```

你会看到类似这样的列表（**新的在最上面**）：

```
Available backups (newest first):

  backups/backup-2026-05-29T10-51-09-948Z.json
      2026-05-29T10:51:11.629Z  ·  5.6 KB
  backups/backup-2026-05-28T03-00-00-000Z.json
      2026-05-28T03:00:00.000Z  ·  5.4 KB
  ...
```

👉 **挑一个出事之前的备份。** 一般选最近的那个（最上面的）。看时间：`2026-05-29T10-51` 表示 5月29日 10点51分 的备份。

把你选中那一行的文件名**完整复制**下来，例如：
`backups/backup-2026-05-29T10-51-09-948Z.json`

---

## 👀 第三步：先预览，确认这个备份没问题（不会改数据）

把上一步复制的文件名，填到下面命令的 `<文件名>` 位置：

```bash
node restore.js --file <文件名> --dry-run
```

实际例子：

```bash
node restore.js --file backups/backup-2026-05-29T10-51-09-948Z.json --dry-run
```

它会显示这个备份里有多少数据，例如：

```
[RESTORE] Backup created at: 2026-05-29T10:51:09Z
[RESTORE] Contents:
            users: 12 rows
            orders: 34 rows
            ...
[RESTORE] DRY RUN — nothing was written to the database.
```

👉 **这一步只是看，不会动数据库。** 确认行数大致正常（比如订单数看起来对），再做下一步。

---

## ✅ 第四步：正式恢复

确认无误后，把命令里的 `--dry-run` 换成 `--confirm`：

```bash
node restore.js --file <文件名> --confirm
```

实际例子：

```bash
node restore.js --file backups/backup-2026-05-29T10-51-09-948Z.json --confirm
```

系统会：
1. **先自动把"现在的数据"存一份快照**（万一恢复错了能反悔）
2. 再把备份数据写回数据库

完成后会显示：

```
[RESTORE] ✅ Restore complete.
[RESTORE] Pre-restore snapshot is at: backups/pre-restore-XXXX.json
```

👉 **记下那行 `pre-restore-XXXX.json` 的文件名**（拍照或复制保存）。这是恢复前的快照，万一你恢复错了版本，还能用它退回去。

---

## 🔄 万一恢复错了，想退回去

如果恢复完发现选错了备份，用上一步记下的 `pre-restore-XXXX.json` 再恢复一次，就回到恢复前的状态了：

```bash
node restore.js --file backups/pre-restore-XXXX.json --confirm
```

---

## ❓ 常见问题

**Q：恢复会把现在的数据全删掉吗？**
A：不会。恢复用的是"覆盖+补回"策略——备份里有的数据会写回去，备份之后新增的数据会保留，不会删除。

**Q：会丢数据吗？**
A：只会丢"最后一次备份之后"产生的新数据。比如今天上午出事，用今天凌晨的备份，最多丢上午几小时的订单。所以发现问题要尽快处理。

**Q：备份存在哪？会不会也丢了？**
A：备份存在 Cloudflare R2（和数据库 D1 是不同的服务），数据库坏了备份还在。每天自动备份，保留最近 30 天。

**Q：命令报错怎么办？**
A：把报错信息截图保存，联系技术支持。不要反复乱试。
